<Note>
**Automated pipeline:** when you use `POST /ingest/{clientOrgId}`, poll
`GET /pipeline/status/{clientOrgId}` — not individual job IDs. The org-scoped
per-stage manual trigger endpoints have been **removed**; this page now only
covers polling jobs created by the two remaining **global** (non-org-scoped)
endpoints: `POST /controls/extract` and the generic `POST /jobs`.
</Note>

`GET /jobs/{jobId}` polls any job created by the two legacy global endpoints
below. The pattern is explained in [Background Jobs](/process/background-jobs).

## Poll job status

```http
GET /jobs/{jobId}
```

**Auth:** Bearer

Repeat until `status` is `completed` or `failed`.

### Response `200`

```json
{
  "id": "uuid",
  "type": "extract_controls",
  "status": "pending | running | completed | failed",
  "payload": { "progress": {} },
  "error": null,
  "created_at": "…",
  "updated_at": "…"
}
```

| HTTP | code |
| --- | --- |
| 404 | `not_found` |

### Status values

| Status | Meaning |
| --- | --- |
| `pending` | Created, not yet picked up |
| `running` | Worker is processing |
| `completed` | Finished successfully |
| `failed` | Errored — see the `error` field |

## List recent jobs

```http
GET /jobs?limit=20
```

**Auth:** Bearer

Returns recent jobs with their statuses — handy for a dashboard view of all
in-flight and finished work.

### Job types

| Type | Started by | Notes |
| --- | --- | --- |
| `extract_controls` | `POST /controls/extract` (global) or `POST /jobs`, or automatically by `/ingest` | Org-scoped trigger endpoint removed |
| `issues_from_controls` | `POST /jobs`, or automatically by `/ingest` | Org-scoped trigger endpoint removed |
| `classify_issues` | `POST /jobs` (or chained after issues), or automatically by `/ingest` | Org-scoped trigger endpoint removed |
| `risk_discovery` | `POST /jobs`, or automatically by `/ingest` | Dedicated trigger endpoint removed |
| `score_risks` | `POST /jobs`, or automatically by `/ingest` | Dedicated trigger endpoint removed |
